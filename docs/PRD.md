## 2. プロダクトの目標

MMOゲームの「メンバー」画面のスクリーンショットから、部族メンバーのユーザ名・レベル・名誉をローカル環境で自動的に読み取り、部族名・記録日とともにデータベースへ登録するバッチツールを提供する。

- 週次の記録作業時間を、約1時間から約15分程度に短縮する
- 読み取りの正答率は初期目標として70%以上とする
- 蓄積データを、部族別・メンバー別・記録日別にCSV出力できる

## 3. ユーザーストーリー

### 想定ユーザー（ペルソナ）

- **部族運営者（唯一の利用者）**: 複数の部族（各最大50人）を運営し、週1回、メンバーの状況を記録したいゲームプレイヤー。PCを使い、コマンド操作とデータベースの直接操作が可能。

### ストーリー

| # | ストーリー | 優先度 |
|---|---|---|
| US-01 | 部族運営者として、スクリーンショットを置いたフォルダを指定するだけで読み取り・登録を実行したい。手入力の手間を省き、週次の記録を短時間で終えるため。 | 高 |
| US-02 | 部族運営者として、読み取るデータがどの部族のものかを指定したい。複数の部族の記録を分けて管理するため。 | 高 |
| US-03 | 部族運営者として、記録日が画像の撮影日時、または画像を置いた日付フォルダの名前から自動で設定されるようにしたい。毎回日付を入力する手間を省くため。 | 中 |
| US-04 | 部族運営者として、同じ画像や重なって写ったメンバーを再度取り込んでも重複登録されないようにしたい。画像の撮り直しやスクロールの重なりがあっても安心して運用するため。 | 高 |
| US-05 | 部族運営者として、読み取りが不確実だった箇所を登録後に判別したい。DBを直接書き換えて訂正すべき箇所を素早く見つけるため。 | 中 |
| US-06 | 部族運営者として、メンバーの加入・脱退や名前の表記揺れがあっても履歴が正しく紐付くようにしたい。週ごとの人数変動があっても推移を追えるため。 | 中 |
| US-07 | 部族運営者として、蓄積したデータを部族別・メンバー別・記録日別にCSVで出力したい。表計算ソフトなどで推移を振り返るため。 | 中 |

### 受け入れ条件

| # | 受け入れ条件 |
|---|---|
| US-01 | フォルダパスを引数に指定して実行すると、フォルダ内の全画像（PNG/JPG）が読み取られ、データベースに登録される。確認画面は表示されない。画像以外のファイルは無視される。存在しないパスや画像が0枚の場合はエラーメッセージを表示して終了する。1枚の読み取りに失敗しても他の画像の処理は継続し、失敗した画像のファイル名が実行結果に表示される。メンバーのカードを1枚も読み取れなかった画像（画像の解像度が小さい、メンバー画面ではない等）は「カード未検出」として、失敗とは別にファイル名と確認を促す注意書きが表示される。すべての画像で読み取れなかった場合は警告が表示される。 |
| US-02 | 実行時に部族名を必須で指定する。未指定の場合は実行できない。未登録の部族名を指定した場合は、1件以上のデータを登録するときに新規部族として自動登録する（カードを1枚も読み取れず登録するデータが無い場合は、部族を作成しない。部族名の指定ミスで空の部族ができるのを防ぐため）。 |
| US-03 | 記録日を指定しない場合、画像の撮影日時（メタデータ）が記録日になる。撮影日時が取得できない場合は、画像を置いたフォルダの名前が日付（YYYY-MM-DD または YYYYMMDD）であればその日付を使用する。それも無い場合はファイルの更新日時を使用する。実行時に記録日を指定した場合は、指定値を優先する。 |
| US-04 | 同一部族・同一記録日・同一ユーザ名のデータが既に存在する場合、実行時のオプションで上書き／スキップを選べる（既定はスキップ）。同一実行内で複数画像に同じメンバーが写っている場合は1件として扱う。同じ画像を2回取り込んでもデータ件数が増えない。 |
| US-05 | 読み取りの信頼度が閾値未満の項目、または数値として解釈できない項目には「要確認」フラグがデータベース上に記録され、実行結果にも件数と対象ユーザ名が表示される。 |
| US-06 | メンバーは部族ごとに管理され、記録日ごとの登録有無により加入・脱退が反映される。脱退後のメンバーの過去履歴も参照できる。別名（エイリアス）が登録された名前は、同一メンバーとして紐付けられる。 |
| US-07 | 部族・メンバー・期間を指定して、記録日ごとのレベル・名誉をCSVファイルに出力できる。指定した記録日の部族全メンバー分を出力することもできる。出力はターミナルへの表示を行わず、ファイルに保存する。 |

## 4. 機能要件

### 4.1 画像取り込み

- フォルダパスを指定し、直下の画像ファイル（PNG/JPG）を取り込む
- 取り込み対象は「メンバー」画面のスクリーンショットとする（サンプル: `docs/sample/BASE_INF.PNG`。画像データはメンバー情報を含むため git 管理外とし、手元に配置する）
- 記録日は、実行時に指定した値を優先し、未指定の場合は画像の撮影日時、取得できない場合は画像を置いたフォルダ名の日付、それも無い場合はファイル更新日時とする（スマホから手動コピーすると更新日時が変わるため、日付フォルダの運用を想定する）
- 取り込んだ画像のファイル名とデータの対応を記録する

### 4.2 画面内容の読み取り

- 各メンバーカードから以下を読み取る
  - ユーザ名（日本語・英数字の混在表記を含む）
  - レベル（剣アイコンの数値）
  - 名誉（星アイコンの数値）
- 累計寄付値（宝石アイコンの数値）、最後の部族活動時間は読み取らない（記録対象外）
- 族長カード（画面上部の特別表示）も、通常のメンバーと同様に読み取り対象とする
- 画面下部で見切れているカードは、情報が完全に読み取れない場合は対象外とし、別の画像で読み取る
- 数値のカンマ区切りを正しく数値に変換する
- 各項目に信頼度を付与し、閾値未満のものを「要確認」とする
- 読み取り処理はローカル環境で完結し、画像を外部サービスへ送信しない

### 4.3 データベース登録

- 読み取り結果は、確認画面を介さず、そのままデータベースに登録する
- 登録単位は「部族」「記録日」「ユーザ名」「レベル」「名誉」とする
- 「要確認」の項目にはフラグを付けて登録する
- 同一部族・同一記録日・同一メンバーの重複は、オプションで上書き／スキップを選択して処理する
- 同一実行内で複数画像間に重複したメンバーは、1件にまとめる
- 登録時に元画像との対応関係（画像ファイル名）を保持する
- 登録後のデータ訂正は、運営者がデータベースを直接書き換えて行う（訂正機能は提供しない）

### 4.4 部族・メンバー管理

- 部族は、取り込み時に未登録の部族名が指定され、1件以上のデータを登録する場合に自動登録される（登録するデータが無い場合は、部族を作成しない）
- メンバーは部族ごとに管理し、読み取ったユーザ名を既存メンバーと照合して紐付ける
- 既存メンバーと一致しないユーザ名は、新規メンバーとして登録する
- 誤読名の別名（エイリアス）をデータベースに登録でき、次回以降の照合に使用する（別名の登録はデータベースの直接操作で行う）

### 4.5 CSV出力

- 部族・メンバー・記録日（期間）を指定して、レベルと名誉の推移をCSVに出力する
- 指定した記録日の部族全メンバーのデータをCSVに出力する
- ターミナルへのデータ表示機能は提供しない

## 5. 非機能要件

| 項目 | 要件 |
|---|---|
| 言語 | Python 3.14（依存ライブラリが未対応の場合は 3.13 → 3.12。EDD 2.1・ADR-002 で確定） |
| インターフェース | CLI（バッチ処理）。将来の画面化は対象外 |
| 精度 | 読み取りの正答率70%以上（初期目標）。正答率は、項目単位（ユーザ名・レベル・名誉）の正解数／全項目数で測定する。ユーザ名を読み取れず正解データと突き合わせられないメンバーは、レベル・名誉も含めて3項目とも不正解として数える。測定は、サンプル画像10枚程度・30人分に対する運営者の正解データとの比較で行う |
| 性能 | 1部族（50人、画像約10枚程度を想定）の読み取りから登録までを数分以内に完了する。週次の記録作業全体（登録後の確認・DB訂正を含む）を15分程度に収める |
| 信頼性 | 登録はトランザクションで行い、途中で失敗した場合は部分的なデータを残さない。読み取り途中で失敗した画像があっても、他の画像の処理は継続し、失敗した画像を報告する。カードを1枚も読み取れなかった画像も報告する |
| セキュリティ | 利用者は運営者のみ。画像の読み取りはローカル環境で完結し、画像・データを外部へ送信しない。設定値は `.env` で管理する |
| データ保全 | データベースのバックアップ方法を提供する（方式は EDD 4.3 で確定: SQLite の `.backup` を運用手順として提供する） |
| 保守性 | ゲームのUI変更に備え、画面レイアウトに依存する読み取り設定（領域座標など）は設定ファイルで管理し、コードに直接記載しない |
| 技術選定 | 読み取り方式・ライブラリ・データベースは、ローカル完結の制約のもとで EDD にて決定済み（ADR-002〜004）。セットアップ時のみ外部から学習データ等を取得し、実行時は外部へ通信しない |

## 6. 画面・インターフェース仕様

### コマンド例（コマンド名・オプション名は EDD 5.8 で確定）

```
# 部族「ABC」の画像を読み取り、そのまま登録する（記録日は撮影日時またはフォルダ名の日付）
liver-stats import --dir ./screenshots/2026-11-22 --tribe ABC

# 記録日を指定して取り込む
liver-stats import --dir ./screenshots --tribe ABC --date 2026-11-22

# 既存データがある場合の扱いを指定する（overwrite / skip。既定は skip）
liver-stats import --dir ./screenshots --tribe ABC --on-conflict overwrite

# 指定した記録日の部族全メンバーをCSVに出力
liver-stats export --tribe ABC --date 2026-11-22 --out members.csv

# メンバーの推移を期間指定でCSVに出力
liver-stats export --tribe ABC --member alice --from 2026-10-01 --to 2026-11-22 --out history.csv
```

### 実行結果の表示例

```
部族: ABC / 記録日: 2026-11-22
画像: 10枚（成功 10 / 失敗 0 / カード未検出 0）
登録: 39件（新規 37 / 上書き 0 / スキップ 2）
要確認: 3件（ももか, ZedKnight, ...）
```

### CSVの出力項目（EDD 5.7 で確定）

`部族名, 記録日, ユーザ名, レベル, 名誉, 要確認`

## 7. スコープ

### In Scope（対象）

- フォルダ指定による画像のバッチ取り込み（CLI）
- 「メンバー」画面からのユーザ名・レベル・名誉のローカル読み取り
- 確認画面を介さない、データベースへの直接登録（重複防止・「要確認」フラグを含む）
- 記録日の自動設定（撮影日時、フォルダ名の日付、ファイル更新日時の順）
- 部族・メンバー管理
- 蓄積データのCSV出力

### Out of Scope（対象外）

- Web画面等からの画像アップロード
- 読み取り結果の確認・修正画面
- 登録後データの訂正機能（データベースの直接書き換えで対応）
- ターミナルでのデータ表示
- 外部の画像認識サービスへの画像送信
- ゲームクライアントの自動操作、スクリーンショットの自動撮影
- 画面画像以外からのデータ取得
- 累計寄付値、最後の部族活動時間など、3項目以外の記録
- 「メンバー」画面以外の画面種別への対応
- 運営者以外の利用者への対応、外部公開・共有
- グラフ表示・ランキングなどの高度な分析
