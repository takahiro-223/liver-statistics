# ドキュメントメンテナンスルール

このファイルは **{{PROJECT_NAME}} プロジェクトにおけるドキュメント管理・メンテナンスに関するルール**を定めたファイルです。
ドキュメントの作成・修正を行う際は、必ずこのファイルを参照し、ルールに従って作業を行ってください。

---

## BRD・PRD・EDD 作成・修正前の確認ルール

機能の追加指示が出た際は、各ドキュメントの作成・修正を開始する前に以下を確認すること。

1. **過去のフィードバックファイルをすべて参照し、未完了の指摘事項がないかを確認する**
   - BRD: `docs/REVIEW/BRD/` 配下のすべての `FEEDBACK_*.md`
   - PRD: `docs/REVIEW/PRD/` 配下のすべての `FEEDBACK_*.md`
   - EDD: `docs/REVIEW/EDD/` 配下のすべての `FEEDBACK_*.md`
   - ステータスが「未完了」の指摘事項が残っている場合は、ユーザーに回答の入力を求め、作業を一時停止すること

2. **過去の指摘事項とその回答内容を参照し、同様の指摘が再発しないよう努めること**
   - 過去に指摘された観点を事前に確認し、同じ問題が新しいドキュメントに含まれないようにすること

---

## BRD修正時のルール

1. **BRDに修正が入った場合は、修正内容が妥当かどうかをレビューすること**

2. **レビュー時の確認観点は `docs/.claude/skills/BRD_review/skill.md` に記載されている内容を参照すること**

3. **レビューで指摘された事項は、すぐに BRD へ反映しないこと。以下の手順に従うこと**

   - 指摘事項を `docs/REVIEW/BRD/FEEDBACK_YYYYMMDD.md`（YYYYMMDD はレビュー実施日）に記録する
   - ファイルの記載形式は以下の通りとする:
     ```
     # BRD フィードバック

     **修正契機:** <BRD修正のきっかけとなった要求内容> （要求日: YYYY-MM-DD）

     ---

     ## 指摘事項

     ### No.1
     **指摘:** <指摘内容>
     **回答:** （未入力）
     **ステータス:** 未完了

     ### No.2
     ...
     ```
   - フィードバックファイルを作成したら、ユーザーに回答の入力を促すメッセージを出力し、作業を一時停止すること
   - **BRD への反映は、ユーザーから「BRD を作成してください」等の再作成指示を受けてから行うこと**
   - 再作成時は、フィードバックファイルの指摘事項とその回答内容をすべて BRD に反映すること
   - 一度指摘してフィードバックファイルに記録した事項に対して、再指摘はしないこと

4. **レビュー指摘を反映した後の BRD に対して、再レビューは行わないこと**

5. **BRD の修正が完了したら、PRD および EDD を作成し、BRD と同様にレビューを実施すること**
   - PRD のレビュー観点: `docs/.claude/skills/PRD_review/skill.md`
   - EDD のレビュー観点: `docs/.claude/skills/EDD_review/skill.md`

## PRD修正時のルール

PRD のレビューについても BRD と同様のルールを適用する。

- 指摘事項のフィードバックファイル保存先: `docs/REVIEW/PRD/FEEDBACK_YYYYMMDD.md`
- それ以外の手順（フィードバック記録 → 一時停止 → 再作成指示で反映 → 再指摘なし）はBRDと同じとする

## EDD修正時のルール

EDD のレビューについても BRD と同様のルールを適用する。

- 指摘事項のフィードバックファイル保存先: `docs/REVIEW/EDD/FEEDBACK_YYYYMMDD.md`
- それ以外の手順（フィードバック記録 → 一時停止 → 再作成指示で反映 → 再指摘なし）はBRDと同じとする

## その他のドキュメントに関するルール

6. **BRD・PRD・EDD 以外のドキュメントが新規作成された場合も、同様にレビューを実施すること**
   - ただし、作成したドキュメントに対応するレビュー観点ファイル (`docs/.claude/skills/<ドキュメント種別>_review/skill.md`) が存在しない場合は、レビュー不要とする
