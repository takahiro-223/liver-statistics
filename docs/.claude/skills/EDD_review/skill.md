# EDD レビュー観点

このファイルは **EDD (Engineering Design Document) のレビュー時に確認すべき観点**を定めたファイルです。
EDD のレビューを行う際は、以下の観点をすべて確認してください。

---

## レビュー観点

### 1. BRD との整合性
**BRD に記載されている内容と矛盾がないか**。
- EDD の設計方針・技術選定が BRD の目的・スコープと一致しているか
- BRD で定義されたスコープ対象外の設計が含まれていないか
- BRD の完了条件を実現できる設計になっているか

### 2. PRD との整合性
**PRD に記載されている内容と矛盾がないか**。
- PRD で定義されたすべての機能要件が設計に反映されているか
- PRD で定義された非機能要件（性能・セキュリティ・可用性等）を満たす設計になっているか
- PRD のユーザーストーリー・受け入れ条件を実現できる設計になっているか

### 3. 記載粒度の適切性
**EDD の記載粒度が適切であるか**。
- 実装者が設計書だけを見て実装に着手できる粒度で記載されているか
- 抽象的すぎて解釈が複数生じる箇所がないか
- 逆に過剰に詳細すぎて保守コストが高くなっていないか
- API・インターフェース・データ構造などの仕様が具体的に定義されているか

### 4. プロジェクト複雑度に応じたドキュメント構成
**プロジェクトの複雑度に応じて、適切な粒度でドキュメントが分割・作成されているか**。
- テーブル数が5つを超える場合、一つのドキュメントにすべて記載せず、以下が作成されているか
  - テーブルごとの個別設計書
  - E-R図（テーブル間のリレーションを示す図）
- モジュール・コンポーネントが多岐にわたる場合、対象ごとに設計書が分割されているか
- 全体像を把握するためのアーキテクチャ概要図・インデックスが用意されているか
