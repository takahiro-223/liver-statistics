# 実装レビュー観点

このファイルは **実装コードのレビュー時に確認すべき観点**を定めたファイルです。
実装のレビューを行う際は、以下の観点をすべて確認してください。

---

## レビュー観点

### 1. EDD との整合性
**実装内容が EDD (Engineering Design Document) の設計仕様と一致しているか**。
- モジュールのインターフェース（関数名・引数・戻り値の型）が EDD の定義と一致しているか
- データベーススキーマ（テーブル名・カラム名・型・制約）が EDD の定義と一致しているか
- EDD で定義された例外クラスが正しく実装・raise されているか
- EDD に記載されていない処理が実装に追加されている場合、設計変更として EDD に反映されているか

### 2. 設定管理の徹底
**設定値がすべて `config.py` および `.env` で管理されており、コードにハードコードされていないか**。
- 接続情報・タイムアウト値・モデル名等が `config.py` 経由で参照されているか
- `.env.example` に必要な環境変数がすべて記載されているか
- デフォルト値がある場合、`config.py` 内で明示されているか

### 3. エラーハンドリング
**エラーが適切に検出・伝播・通知されているか**。
- `except Exception` など過剰に広い例外捕捉を行っていないか（必要な場合は理由をコメントで明示）
- エラーが発生した際に、原因が特定できる情報をメッセージに含めているか
- データが空文字・None の場合など境界ケースに対して適切に対処しているか

### 4. セキュリティ
**セキュリティ上の脆弱性が存在しないか**。
- SQL クエリはプレースホルダ（パラメータ化クエリ）を使用しており、SQL インジェクションのリスクがないか
- 認証情報・シークレットがコードやログに平文で出力されていないか
- 外部リクエスト時に `timeout` を必ず設定しているか（無制限の待機を防ぐ）

### 5. パフォーマンス
**不要な処理が行われておらず、効率的な実装になっているか**。
- 重いリソース（モデル・DB接続等）のロードはシングルトンパターンで1回のみ実行されているか
- DB 接続はコネクションプールまたは適切なスコープで管理されており、不要な接続が残らないか
- バッチ処理が可能な箇所でループ処理になっていないか

### 6. ディレクトリ構成の遵守
**ファイルが `.claude/rules/directory_structure.md` で定められた構成に配置されているか**。
- 各モジュールが役割に対応するディレクトリに置かれているか
- `scripts/` 配下のスクリプトがビジネスロジックを持たず、統合レイヤーを呼び出す構造になっているか

### 7. テスト容易性
**コードがユニットテスト・インテグレーションテストを書きやすい構造になっているか**。
- 副作用（DB・HTTP・ファイルI/O）を持つ処理と純粋なロジックが分離されているか
- グローバル状態への依存が最小限に抑えられているか
- `tests/unit/` および `tests/integration/` にそれぞれ対応するテストファイルが存在するか
